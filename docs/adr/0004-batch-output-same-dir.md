# ADR-0004: 批量输出目录等于输入目录时允许，但前端明确不可恢复风险并二次确认

## 状态

已接受 (Accepted) — 2026-08-11

## 背景

批量编辑视图允许用户自由选择输出目录。当前 Rust 端 `execute_batch_processing`（`src-tauri/src/image_ops.rs`）只在**同批次内重名**时自动加后缀重命名；当输出目录等于输入目录且队列中文件不重名时，处理结果会**直接覆盖原图**——用户原图不可恢复。

用户存在真实工作流：批量压缩/格式转换后希望原地替换原图。一刀切禁止同目录会破坏该工作流。

## 决策

**允许**输出目录等于输入目录，但前端（批量编辑视图）必须在开始处理前：

1. 检测到输出目录 == 任一待处理图片所在目录时，弹出明确警告对话框，文案必须包含：
   - "原图将被覆盖，此操作不可恢复"
   - 处理规则说明（不备份、覆盖前不再弹窗）
2. 用户**二次确认**后才调用 `batch_process_queue`；取消则完全不执行
3. Rust 端不新增禁止/拒绝逻辑——同目录是合法输入，保持现有覆盖行为不变

## 备选方案

### 备选 A：禁止输出目录等于输入目录（前端拦截 + Rust 校验）

- ✅ 绝对安全，零覆盖风险
- ❌ 破坏"原地替换原图"的真实工作流
- ❌ 需要新增 Rust 校验逻辑，改变命令语义

### 备选 B：自动重命名不覆盖（同目录时输出加后缀）

- ✅ 原图永不丢失
- ❌ 用户预期是原地替换，结果目录出现 `a_1.jpg`，语义混乱
- ❌ 与"处理后的图片按原文件名保存"的既有说明冲突

### 备选 C：允许 + 前端二次确认（✅ 已采纳）

- ✅ 保留原地替换工作流
- ✅ 覆盖风险由用户明确知情并确认，责任归属清晰
- ✅ 仅前端交互变更，Rust 端零改动
- ❌ 用户误确认后仍可能丢失原图（可接受，因已明确警告）

## 后果

- `src/components/BatchTab.tsx` 增加同目录检测与确认对话框交互
- 确认交互必须有自动化测试（Vitest）：同目录时警告出现、确认后调用 invoke、取消不调用
- 批量处理（`batch_process_queue`）命令签名与行为不变
- 无备份机制，原图覆盖不可恢复（文档中明确告知用户）
