# ADR-0002: 队列面板仅在批量编辑视图出现

## 状态

已接受 (Accepted) — 2026-06-14

## 背景

新设计里，"队列"是把图片从浏览视图挑出来、送去批量处理的中间结构。问题是：队列的可视化（队列面板）应该在哪里出现？

## 决策

**队列面板只在批量编辑视图出现**。浏览视图不显示队列、不维护队列。

加入队列的入口：
- 浏览视图 → 右键缩略图 → 菜单 → "加入队列"（**唯一入口**，无工具栏按钮）
- 单图编辑视图 → "加入队列并打开下一张" 按钮

## 备选方案

### 备选 A：队列面板常驻右侧（类似 IDE 项目面板）

- ✅ 随时可见，用户有"掌控感"
- ❌ 浏览视图是"看图为主"，常驻面板会**永久占 240px**，缩略图列数减少
- ❌ 用户浏览图片时并不需要看队列，UI 噪声
- ❌ 不支持拖拽加队列（浏览视图不显示），那常驻的"加入队列"按钮反而冗余

### 备选 B：队列面板常驻，但可折叠到 0

- ✅ 用户可完全收起
- ❌ 折叠 = 隐藏 = 用户忘记队列存在
- ❌ "队列在哪"这个问题永远存在

### 备选 C：浏览视图显示一个"队列数量徽章"（小圆点）

- ✅ 浏览视图不占地方，仅一个小红点
- ❌ 增加心智负担："点这个徽章会跳到批量视图？"
- ❌ 不解决"在浏览视图加队列"的问题

## 后果

- 队列逻辑**只**在 `BatchView` 内消费
- 浏览视图的"加入队列"动作做完后**自动切换到批量视图**，让用户立刻看到结果
- 单图编辑视图的"加入队列并打开下一张"是**隐式 Enqueue**（用户没察觉）
- 队列状态存在 Zustand store 的 `queue: QueueItem[]` slice
