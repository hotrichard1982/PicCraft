# BUG-001 单图裁剪遮罩不同步

## 背景

- 报告人：老吴
- 日期：2026-07-14
- 分支：`main`
- 模块：单图编辑 / 自由裁剪预览

单图编辑的预览区使用 Konva 绘制图片、红色裁剪框和四块半透明遮罩。裁剪框表示最终裁剪范围，遮罩中间的透亮区域应始终与裁剪框完全重合。

## 现象与复现

1. 进入单图编辑并选择任意图片。
2. 在预览区拖出一个裁剪框。
3. 拖动裁剪框，或使用控制点调整裁剪框大小。
4. 红色裁剪框移动或缩放成功，但遮罩的透亮区域仍停留在旧位置。

真实程序已使用 `public/logo.png` 复现。窗口尺寸变化导致图片重新适配时，同一问题也可能出现。

## 根因分析

`src/components/CropCanvas.tsx` 中，裁剪框和遮罩采用两条不同的更新路径：

- `updateOverlay` 通过 Konva 引用直接更新四块遮罩。
- 它只在首次画框的 `handleMouseMove` 中调用。
- `handleDragEnd`、`handleTransformEnd` 只更新父组件的 `cropRect`。
- 监听 `cropRect` 的 effect 只显示或隐藏裁剪 UI，没有根据最新 `cropRect`、画布缩放和偏移重新计算遮罩。

因此红色裁剪框会随 React 属性更新，而遮罩保留上一次命令式写入的坐标，形成错位。

## 影响与风险

- 严重程度：中等
- 用户影响：预览反馈错误，容易误判实际裁剪范围。
- 数据影响：当前裁剪命令仍读取最新 `cropRect`，未发现原图损坏或错误坐标写入。
- 修复风险：低；只需统一遮罩坐标同步，不涉及 Rust 图片处理、持久化、权限或依赖变更。

## 目标

保证裁剪框在首次绘制、拖动、缩放和画布尺寸变化后，半透明遮罩的透亮区域始终与裁剪框一致。

## 验收标准

- [x] 回归测试先在旧实现上失败，并明确证明最新裁剪框坐标没有同步到遮罩。
- [x] 首次绘制裁剪框时，红框和遮罩透亮区域重合。
- [x] 拖动裁剪框后，遮罩立即与新位置重合。
- [x] 缩放裁剪框后，遮罩立即与新尺寸重合。
- [x] 画布尺寸或图片适配比例变化后，遮罩仍与裁剪框重合。
- [x] 现有单图编辑与前端测试通过。
- [x] 本次变更的 lint、类型构建与文档链接校验通过；全仓既有 Doctor/lint 债务已记录。
- [x] 重新生成 Windows EXE，并核对产物存在且更新时间属于本次构建。

## 修复记录

- 修复日期：2026-07-15
- 修复方案：将四块遮罩的坐标计算收敛到 `calculateOverlayRects`，首次拖画与后续 React 渲染共用同一计算；`cropRect`、缩放、偏移或舞台尺寸变化时都会重新生成遮罩坐标。
- 自动化证据：Vitest 4 个回归测试先失败后通过；全量前端测试 34/34 通过。
- 构建证据：`dist/piccarft.exe`、MSI、NSIS 安装包已重新生成。
- 验收人：老吴（2026-07-15，真实界面验收通过）。
